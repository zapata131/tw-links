## {% include icon.html name="guides" %} Guides & Case Studies {#guides}

- [Docs as Code (Write the Docs Guide)](https://www.writethedocs.org/guide/docs-as-code/):
  A guide to writing and managing docs with the same tools developers use for
  code, like Markdown, Git, and code reviews.
- [Diátaxis](https://diataxis.fr/): Daniele Procida's framework that splits
  documentation into four types: tutorials, how-to guides, reference, and
  explanation. It's a useful way to think about docs, though I have my
  reservations about how strictly people sometimes apply it.
- [GitHub Docs (Open Source Repo)](https://github.com/github/docs): The public
  repository for GitHub's docs. Useful if you want to see how a large team
  organizes content and docs-as-code workflows.
- [Writing for Web Accessibility (W3C)](https://www.w3.org/WAI/tips/writing/):
  Short tips from the W3C on writing accessible headings, link text, alt text,
  and instructions.
- [Growth.Design Case Studies](https://growth.design/case-studies): UX case
  studies in a comic-book format. Great for learning how to write short, clear
  interface copy.
- [Ask me about API docs](https://askmeaboutapis.com/): A unique page written by
  Clarence William Cromwell that has a set of guides and essays, for both
  developers and technical writers, about writing API documentation.
- [OpenAPI Learning Portal](https://learn.openapis.org/): The official guide
  from the OpenAPI Initiative on how to read and write OpenAPI specifications.

## {% include icon.html name="tools" %} Tools & Reference {#tools}

- [Google developer documentation style guide](https://developers.google.com/style/):
  A complete style guide for technical writers. Highly suggested if you are a
  solo writer or starting a technical writing team. (Don't reinvent the wheel.)
- [The Good Docs Project](https://www.thegooddocsproject.dev/): Templates and
  checklists for common types of technical documentation, like READMEs and API
  references.
- [Merriam-Webster.com](https://merriam-webster.com): For all your spelling needs.
- [Markdown Guide](https://www.markdownguide.org/): A cheat sheet and reference
  for Markdown syntax. Handy to bookmark or share with engineers who contribute
  to your docs.
- [The Art of Command Line](https://github.com/jlevy/the-art-of-command-line):
  Useful if you need to be fluent in using the command line in *NIX systems.
- [Excalidraw](https://excalidraw.com/): A free, open-source whiteboard with a
  hand-drawn style. Good for sketching quick architecture diagrams and flows.
- [Mermaid](https://mermaid.js.org/): Diagrams as code. Lets you write
  flowcharts and sequence diagrams in Markdown so they stay in Git alongside
  your docs.
- [Vale](https://vale.sh/): An open-source linter for prose. It checks your
  writing against a style guide (like Google's or Microsoft's) right in your
  editor.
- [Doc Detective](https://docs.doc-detective.com/): An open-source tool for
  testing documentation. It runs automated checks to verify that your UI steps,
  CLI commands, and API calls still work.
- [llms.txt](https://llmstxt.org/): A proposed Markdown format for making
  documentation easier for LLMs and AI coding tools to read.

## {% include icon.html name="courses" %} Courses {#courses}

- [Google's Technical writing courses](https://developers.google.com/tech-writing/overview):
  Four courses about the basics of technical writing, including writing for
  accessibility and writing error messages.
- [Learn Git Branching](https://learngitbranching.js.org/): An interactive
  sandbox for practicing Git. Helpful if you are new to docs-as-code and want to
  get comfortable with branches and merges.
- [Documenting APIs: A guide for technical writers and engineers](https://idratherbewriting.com/learnapidoc/):
  A course by Tom Johnson, the author of the I'd Rather be Writing blog. A
  complete guide to learn everything you need to know about REST APIs,
  documenting endpoints, using the OpenAPI spec, and more.

## {% include icon.html name="books" %} Books {#books}

### Technical writing

- [Modern Technical Writing: An Introduction to Software Documentation](https://www.amazon.com/Modern-Technical-Writing-Introduction-Documentation-ebook/dp/B01A2QL9SS/):
  By Andrew Etter. A short, plain-spoken intro to modern software documentation.
- [Docs for Developers](https://www.amazon.com/Docs-Developers-Engineers-Technical-Writing-ebook/dp/B09HLZGWKT/):
  By Jared Bhatti, Jen Lambourne, David Nunez, et al. Written with engineers in
  mind, it walks through planning, writing, and maintaining software docs.
- [Docs Like Code](https://www.docslikecode.com/book/): By Anne Gentle. About
  using software development tools like Git and automated builds to publish
  documentation.
- [Every Page is Page One](https://xmlpress.net/publications/eppo/): By Mark
  Baker. Explains the topic-based approach to writing documentation for the web.
- [Docs as Tests](https://www.docsastests.com/): By Manny Silva. Shows how to
  test your documentation like software so your examples stay accurate as the
  product changes.
- [The Product is Docs](https://www.amazon.com/Product-Docs-technical-documentation-development-ebook/dp/B085KHTV95/):
  By Christopher Gales and the Splunk Documentation Team. About building and
  running a technical writing team inside a software company.
- [Documentation at Scale](https://www.amazon.com/dp/B0HGPRKYMN): By Andrew
  Etter. A follow-up to *Modern Technical Writing* about managing larger doc
  sets and working with AI.

> *Note: To learn more about some of these books, you can read the
> [Three books to boost your technical writing career](https://bufferbuffer.com/three-books-to-boost-your-technical-writing-career/)
> post.*

### APIs and UX writing

- [Web API Design Crafting Interfaces that Developers Love](https://www.academia.edu/11335664/Web_API_Design_Crafting_Interfaces_that_Developers_Love):
  By Brian Mulloy. This book with a Creative Commons license is a good read if
  you want to get involved in helping design and document REST APIs.
- [Strategic Writing for UX](https://www.amazon.com/Strategic-Writing-Engagement-Conversion-Retention/dp/1492049395/):
  By Torrey Podmajersky. This book is a good read if you are involved with UX
  writing or want to learn more about the subject.
- [Microcopy: The Complete Guide](https://www.microcopybook.com/): By Kinneret
  Yifrah. A companion to *Strategic Writing for UX* with plenty of examples of
  buttons, empty states, and error messages.

## {% include icon.html name="blogs" %} Blogs {#blogs}

- [I'd Rather be Writing](https://idratherbewriting.com/): Written by Tom
  Johnson, a technical writer working at Google. He has interesting post series
  about different topics related to technical writing.
- [Passo Uno](https://passo.uno/): Written by Fabrizio Ferri Benedetti, a
  technical and UX writer working at Elastic. His posts vary from editorial
  pieces to in-depth discussions about the current state of technical writing.
- [This is important](https://thisisimportant.net/): Written by Sarah Moir, a
  technical writer at Sigma. Her unique vision of combining data analysis and
  technical writing, plus the way she guides you through her thinking process,
  make this blog an interesting read.
- [Docs Like Code blog](https://www.docslikecode.com/): Anne Gentle's blog about
  docs-as-code and developer portals.
- [Every Page is Page One blog](https://everypageispageone.com/): Mark Baker's
  blog about topic-based writing and how people actually search for docs on the
  web.

## {% include icon.html name="podcasts" %} Podcasts {#podcasts}

- [The Not-Boring Tech Writer](https://thenotboringtechwriter.com/): A casual
  podcast about the day-to-day of technical writing, including career paths,
  imposter syndrome, and working with engineers.
- [Write the Docs Podcast](https://podcast.writethedocs.org/): Group
  conversations with technical writers about documentation tools, habits, and
  experiences.
- [The Cherryleaf Podcast](https://www.cherryleaf.com/podcast/): Hosted by Ellis
  Pratt, with interviews about technical communication, managing doc teams, and
  AI.

## {% include icon.html name="communities" %} Communities & Conferences {#communities}

- [Write the Docs](https://www.writethedocs.org/): "A global community of people
  who care about documentation." They organize annual conferences in Portland,
  Berlin, Kenya, and Australia, and meetups across the globe. The page has some
  interesting resources and a wholesome Slack community.
- [API the Docs](https://apithedocs.org/): An online conference focusing
  exclusively on API documentation.
- [tcworld conference](https://tcworldconference.tekom.de/): A large annual
  technical communication conference held every fall in Stuttgart, Germany. It
  is more traditional than Write the Docs, with talks on structured content and
  compliance.
